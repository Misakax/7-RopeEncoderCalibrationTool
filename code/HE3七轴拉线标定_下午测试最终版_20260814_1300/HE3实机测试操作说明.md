# HE3 七轴拉线标定实机测试操作说明

## 当前版本能做什么

当前版本允许在人工确认下执行：连接 HE3_GY、上电、回零、自动运行 60 个关节点位、采集实际关节角和拉线长度、自动运行 `CalibrationV2`、保存完整诊断报告。

上位机启动后会自动选择 `HE3_GY` 和“拉线编码器”。计算结束后，训练/全点与留出验证点的拉线平均残差都必须不大于 **1.0 mm**，并且 DLL 状态必须成功，界面才显示“计算通过”。这里的 1.0 mm 是拉线距离模型门槛，不代表三维绝对定位精度已经达到 1.0 mm。

当前版本**禁止把 CalibrationV2 参数写回控制器**。代码中的 `kEnableV2WriteBack=false` 是强制安全锁。原因是现有旧写回代码只覆盖六个关节，而 HE3 七轴的控制器参数 ID、长度单位、零位存储单位、方向符号和回滚流程尚未取得正式定义。点击“保存/写回”会被拦截并写入日志。

拉线原始计数到毫米的换算系数已从旧界面的隐藏常量移到 `RopeEncoderCalibration/Config/RobotType/HE3_GY-cfg.txt` 第 16 项，当前值仍为原程序使用的 `284.94 counts/mm`。程序会把该值写入机器日志和标定报告；没有拉线编码器计量证书或现场标尺校核结果时不要修改。

程序在计算前还会强制检查：正好收到 60 组七轴实际反馈、60 个拉线格均非空且可解析、加上治具偏置后的每个长度均为正数。任一条件不满足都会拒绝启动 DLL，不再把空白数据静默当成 0。

## 运行前必须满足

1. 测试对象必须选择 `HE3_GY`，配置必须显示 7 轴、60 点。
2. 急停必须有效，操作人员始终能触及急停。
3. 工作区无人、无障碍物，60 个点位已经逐点完成碰撞和关节限位检查。
4. 拉线固定端、末端连接件和工具安装牢固；拉线在全部点位中不会缠绕、刮擦、卡死或超过量程。
5. 先用最低速度档 `20`；不要在第一次测试提高速度。
6. 控制器、上位机和拉线编码器通信地址已经由现场负责人确认。
7. 已备份机器人当前配置。虽然本版本锁住了算法参数写回，仍建议保留测试前备份。
8. 第一次运行至少两人配合：一人操作软件，一人观察机器人和拉线。

任一条件不满足，不要开始。

## 编译与版本核对

1. 双击根目录的 `RopeEncoderCalibrationTool.sln`，Visual Studio 顶部选择 `Debug | x86`。
2. 执行“生成 -> 重新生成解决方案”。
3. 必须看到三个项目成功：
   - `MathematicalDLL`
   - `MathematicalDLLTests`
   - `RopeEncoderCalibrationTool`
4. 运行 `Debug\MathematicalDLLTests.exe`，最后必须显示 `ALL TESTS PASSED`。
5. 按 F5 启动上位机，在 VS“输出/调试”窗口确认出现：
   - `CONTROLLED MACHINE TEST MODE`
   - `MathematicalDLL CalibrationV2 ...`
   - `V2 write-back=LOCKED`
   - 新建的 `MachineTest_*.log` 路径

若仍显示旧时间、旧 DLL 路径、离线模式，或 DLL 入口断点不命中，不得继续。

## 实机操作顺序

### 1. 选择配置

程序应已自动选择 `HE3_GY` 和“拉线编码器”。再次核对：7 轴、60 点、速度 20。列表中应有 60 行，每行 7 个关节角。

### 2. 连接

点击“连接”，仔细核对确认框里的机器人型号和 IP 后选择“是”。

连接阶段只建立通信并配置运动变量，不自动上电、不自动回零。日志中应看到：

```text
[CONNECT]
[TX]
[RX]
[SETUP] ... no power/home command sent
```

连接失败时不要反复点击开始；保存日志并处理通信问题。

### 3. 读取拉线零点

按界面原有按钮读取拉线编码器当前值，确认零点输入框为有效整数。不要手工随意填入一个数。

### 4. 开始上电和回零

点击“开始”。第一个确认框会列出上电、回零和 60 点动作。现场条件全部满足后才选择“是”。

程序发送上电和 `Robot.Home 1` 后会弹出第二个确认框。此时不要立即点击“是”；先观察机器人，只有在以下条件全部满足后才确认：

- 回零动作已经真正结束；
- 控制器无报警；
- 机器人姿态正常；
- 拉线没有缠绕、卡住或异常受力。

如果不满足，点击“否”，程序会终止并尝试下电。

### 5. 自动运行 60 点

确认回零完成后，程序开始逐点运行。每个点应产生日志：

```text
[POSE_BEGIN] index=N/60
[POSE_COMMAND] ... targetDeg=...
[RX] ...
[POSE_MEASUREMENT] ... rawEncoder=... ropeDeltaMm=...
[POSE_END] index=N ...
```

全过程观察机器人和拉线。出现异响、碰撞风险、拉线刮擦/缠绕、异常跳变、关节超速或报警时，立即按急停；安全后再点击软件“停止”。不要等待程序自己超时。

### 6. 自动保存和离线计算

第 60 点完成后，程序自动保存关节和拉线数据，随后请求机器人下电，再自动调用 `CalibrationV2`。日志应看到：

```text
[RUN_COMPLETE]
[ACQUISITION_COMPLETE]
[POWER_OFF] automatic power-off after acquisition returned 0
[CALIBRATION] starting CalibrationV2 ...
[CALIBRATION] status=...
```

`POWER_OFF` 返回值不是 `0` 时，必须立即从控制器确认伺服状态并人工下电，不要只相信界面状态。

## 结果文件在哪里

程序保留旧上位机原有的工作目录行为，避免改变其通信组件和配置查找方式。实际工作目录会在启动日志的 `workingDirectory=` 中打印。所有相对结果目录都位于该工作目录下；从 VS F5 启动时通常是 `RopeEncoderCalibration` 项目目录，直接双击 Debug EXE 时通常是 `Debug` 目录：

1. `<workingDirectory>\log\MachineTest_*.log`：本次实机全过程日志，最重要。
2. `<workingDirectory>\log\日期_log.txt`：原有 QKMLink 通信日志。
3. `<workingDirectory>\Joint\HE3_GY_Joint_*.txt`：60 点实际关节反馈。
4. `<workingDirectory>\data\HE3_GY_Data_*.txt`：60 点拉线原始数据。
5. `<workingDirectory>\Result\CalibrationV2_HE3_GY_*.txt`：完整算法结果。

V2 报告包含：构建版本、状态码、固定端 XYZ、矩阵秩和条件数、训练/验证集标定前后 MAE、所有候选参数的请求状态和修正量、完整标定前后 MDH、七个零位以及每个采样点的原始长度、有效长度、前后残差和七轴实际角度。

## 怎样判断结果

不能只看“标定后误差变小”。至少检查：

1. `Status` 是否为成功状态；状态不是成功时不得使用参数。
2. `Rank` 是否覆盖全部活动参数，`Condition` 是否异常大。
3. 训练集和 15 点验证集的 MAE 是否都下降。
4. 是否有参数触及长度 `±5 mm` 或零位 `±1°` 边界；触边表示失败或模型/数据有问题。
5. 60 点是否存在单点巨大残差、NaN 或采集错位。
6. 重复测试时参数是否基本一致。
7. 界面是否明确弹出“CalibrationV2 计算通过”；只要状态失败、全点 MAE 或验证点 MAE 任一超过 1.0 mm，界面会显示“结果被拒绝”。

仓库中 2026-06-09 的旧 `HE3_GY` 回放数据与当前配置无法在安全参数范围内拟合到 1.0 mm，因此被正确拒绝。它只能用于验证“坏数据/错版本不会被误报为成功”，不能代表下午这台机器人一定会得到相同残差。

拉线残差下降只证明数据更符合这一个距离模型，不等于三维绝对定位精度已经合格。最终仍需激光跟踪仪或其他独立计量结果验证。

## 为什么现在不能写回

旧代码的写回通道按六轴输出和编码器计数处理，不能直接拿七轴 V2 的米、弧度参数写入。启用写回前必须由控制器/范国华侧提供并确认：

1. HE3 七轴每个允许修改参数对应的正式 IDN 或配置字段；
2. `d2、d3、d4、d5、d7` 的控制器长度单位和正负方向；
3. `q2～q5` 零位在控制器中以弧度、角度还是编码器计数保存；
4. 编码器方向、每圈计数、减速比及零位补偿符号；
5. 写入前备份、写入后校验和失败回滚步骤；
6. 激光/生产验收通过的判据。

在这些映射未确认前，代码不会把 V2 结果写回机器人。这是防止错误参数造成跳变、超速或碰撞。

## 测试后需要一起分析的文件

完成一次测试后，不要只发界面截图。请同时提供上述 5 类文件，并说明机器人序列号、配置版本、工具/拉线安装方式、测试时间、是否出现报警以及现场观察到的异常。只有这些材料齐全，才能给出完整结果和下一步修复判断。
