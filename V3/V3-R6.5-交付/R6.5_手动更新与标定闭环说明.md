# HE3 拉线标定 R6.5 手动更新说明

## 1. R6.5 改了什么

R6.5 不改变 V1 的上位机运动、拉线换算和解析雅可比主链，重点修复“计算结果如何真正进入七轴控制器”的闭环。

- 算法统一使用 Craig MDH：`alpha=[0, alpha1...alpha6]`。
- 控制器 `1101.12` 使用旧式 DH/SDH 顺序且单位为度：`[alpha1...alpha6,alpha7]`。
- 激光方案允许集合显示为：`D2~D5、Alpha1~Alpha7、q2~q6`。
- 拉线轴向测量实际可解：`D2~D5、Alpha1~Alpha6、q2~q6`；q6 解析列为零时保持，Alpha7 对当前位置距离为结构零列，保持控制器值。
- 保存时完整读取 `1101.11`、`1101.12`、`1127.13` 七项，写每一项后立即回读。
- 任何写入或回读失败，不发送 `21.23 save`，并尝试恢复写入前快照。
- 保存成功后再次读取控制器，并转换成下一轮算法的原始 Craig MDH。
- 右侧日志显示输入来源、MDH/SDH 判断、开放参数、每点目标/实际关节、拉线均值和标准差、每轮 MDH/修正量、写前/候选/回读值。

## 2. 手动替换文件

在 V3 工程中备份后替换：

1. `RopeEncoderCalibrationV3\RopeEncoderCalibrationDlg.cpp`
2. `RopeEncoderCalibrationV3\RopeEncoderCalibrationDlg.h`
3. `CalibrationV3Analytic\CalibrationV3Analytic.cpp`

`CalibrationV3Analytic.h` 本次接口没有改变。

## 3. 手动修改时应核对的六处

1. 窗口版本必须含 `R6.5 Closed Loop`。
2. DLL `CalibrationV3BuildId()` 必须返回 `R6.5-CLOSED-LOOP`。
3. 开放参数在 `RunCalibrationV3ForGui()` 的 `active` 数组中定义，不能使用六轴魔法下标。
4. 控制器 Alpha 映射必须为：`Craig alpha[1..6] <-> 1101.12[1..6]`，不能把 Craig 的首个 0 写成 Alpha1。
5. D7 写入控制器时只允许结构长度约 93 mm；49 mm ToolOffset 只在算法输入中相加，不能重复写入。
6. 零位写回仍沿用 V1 符号：`旧零位 + MoveDirection * (-q0角度) * 编码器线数 / 360`。

Visual Studio 选择：

- `Config` 目录

## 5. 操作闭环

1. 启动：右侧先显示本地 HE3_GY Craig MDH 和开放策略。
2. 连接：软件读取控制器 D/Alpha/零位；合理性检查通过后，回读值成为本轮原始输入。
3. 采集：每个点在右侧打印目标关节、实际关节、原始 count、home、距离、样本数和标准差。
4. 计算：打印每轮 anchor、D、Alpha、q0 以及实际应用的 delta。
5. 保存：只在全部安全门限通过后允许。软件下电、读取快照、生成候选、逐项写回和回读、执行 `21.23 save`、再次完整回读。
6. 复验：必须重新运动和重新采集。旧 82 点数据只能做算法复输入检查，不能证明保存后的真实精度。

## 6. 日志位置

所有相对路径均以 EXE 的工作目录为根：

- 通信及右侧镜像：`log\日期_log.txt`

## 7. 进一步提高精度的顺序

1. 先保证启动输入来自控制器回读，而不是又回到名义配置。
2. 先看目标/实际关节误差、拉线标准差和最大残差点；不要只看拟合后 MAE。
3. 用未参与求解的独立点做验证，区分“拟合拉线好”与“绝对定位好”。
4. 保持激光八机参数包络，禁止 D/Alpha 为补偿单个坏点漂到不合理值。
5. 若残差随 J6 单调变化，再检查 J6 柔性、工具轴线和 Alpha6/q6 列相关性；不要直接开放更多参数。
6. 量产最终仍应抽样用激光跟踪仪验证三维绝对精度。拉线 MAE 不是激光三维误差的同义词。
