# HE3 拉线标定 R7.1：公共 MDH + 独立拉线零偏 bL

## 1. R7.1 固定模型契约

R7.1 不再提供 R7 的“控制器 MDH / 原始 MDH”二选一。

每次点击“开始”前，算法输入都强制恢复为：

`Config/RobotType/HE3_GY-cfg.txt`

公共 HE3 配置当前为：

- Craig MDH `a = [0,0,0,0,0,0,0] mm`
- Craig MDH `d = [0,49,493,-120,317,0,93] mm`
- Craig MDH `alpha = [0,90,-90,90,-90,90,-90] deg`
- `theta = 0`
- `beta = 0`
- `ToolOffset = 49 mm`
- 算法内部有效 `D7 = 93 + 49 = 142 mm`

控制器 `1101.11 / 1101.12 / 1127.13` 仍会读取，但只用于写回前后的快照、结构检查和逐项回读验证，不再成为下一轮标定初值。

## 2. R7.1 新增的拉线零偏模型

测量方程改为：

`L_measured = ||P - lambda|| + bL`

其中：

- `P`：当前 Craig MDH 和关节角计算得到的拉线测量点；
- `lambda`：拉线固定端三维坐标；
- `bL`：拉线测量链绝对长度零偏，单位 m（GUI/CSV 显示 mm）。

残差定义为：

`r = L_measured - ||P - lambda|| - bL`

因此 bL 的解析 Jacobian 列恒为 `+1`。

求解变量从原来的：

`[机器人活动参数, lambda_x, lambda_y, lambda_z]`

扩展为：

`[机器人活动参数, lambda_x, lambda_y, lambda_z, bL]`

`bL` 不进入 `4N` 机器人参数向量，不进入 `outDelta4N`，也没有任何控制器写回映射。

## 3. 62.5 mm 固定补偿仍保留

GUI 现有拉线长度链不改：

`L_measured = (count - home_count) / 284.94 + 62.5 mm`

R7.1 不直接把 62.5 改成某个现场值，而是在求解器中辨识剩余的公共零偏 `bL`。

用于理解时，可以换算为等效固定补偿：

`L_corrected = L_measured - bL`

所以：

`fixed_offset_effective = 62.5 mm - bL`

这只是诊断等效值；程序仍保留名义 62.5 mm 常数，避免把某一次装夹偏差固化为全局常数。

## 4. GUI 新增/改名显示

标定结果区显示三项：

1. `拉线零偏 bL(mm)`
2. `去零偏前 MAE(mm)`
3. `去零偏后几何 MAE(mm)`

定义：

- 去零偏前 MAE：公共 MDH 输入、`bL=0` 时的原始长度残差 MAE；
- 去零偏后几何 MAE：联合求解机器人参数、固定端和 bL 后，对 `L_measured - bL` 的剩余几何残差 MAE。

安全门的残差判断使用“去零偏后”的几何残差。满秩仍要求增广 Jacobian 的 `15 + 4` 列全部可辨识。

R7 的 condition 门限原为 `2500`；加入 bL 后，同一 82 点数据的增广矩阵 condition 离线复算约为 `2636`，因此 R7.1 将该门限小幅调整为 `3000`。这是针对新增物理 nuisance 列的维数变化，不改变残差、运动、重复性、激光包络等其他安全门。

## 5. 写回规则

R7.1 的机器人参数开放/保持策略沿用交接文档：

- 求解/候选：`D2~D5`、`Alpha1~Alpha6`、`q2~q6`（q6 仍按可观测性决定是否参与）；
- 保持：`A1~A7`、`D1/D6/D7`、`q1/q7`、`Beta1~Beta7`、`Alpha7`；
- `bL`：只存在于拉线测量链，**永不写入 MDH、零位 count 或控制器参数**。

写回 CSV 增加：

- `rope_bias_mm`
- `rope_bias_written_to_mdh,0`
- `calibration_input_source`（应为公共 HE3_GY 配置）
- `writeback_baseline_source,controller_readback`

## 6. 诊断 CSV 新增字段

R7.1 的 `V3Diagnostic_*.csv` 新增：

- `rope_bias_mm`
- `measurement_model,L_measured=norm(P-lambda)+bL`
- `rope_fixed_offset_nominal_mm,62.5`
- `rope_fixed_offset_effective_mm`
- `mae_before_bias_mm`
- `geometry_mae_after_bias_mm`
- `measurement_nuisance_parameters,anchor_x|anchor_y|anchor_z|bL`
- 迭代记录中的 `rope_bias_mm`
- 每点 `rope_bias_corrected_mm`
- 每点 `residual_before_bias_mm`
- 每点 `residual_after_geometry_mm`

兼容旧分析工具，`mae_before_mm` / `mae_after_mm` 键仍保留，但语义分别对应上述两个 MAE。

## 7. 当前 R7 数据的离线 sanity check

对交付包内 `Result/V3Diagnostic_2026_8_26_15_41.csv` 的 82 个“标定前残差”直接做常量去均值：

- 残差范围：`+1.241110 ~ +6.718510 mm`
- 平均残差：`+2.936891 mm`
- 原始 MAE：`2.936891 mm`
- 仅去统一零偏后的 MAE：`0.658670 mm`

对 R7 已做几何修正后的残差再去均值：

- 平均残差：`+2.464771 mm`
- 去统一零偏后的 MAE：`0.566915 mm`
- 去统一零偏后的最大绝对残差：`3.350409 mm`

这只用于验证当前残差存在强公共模态，不等价于 R7.1 联合优化的最终现场结果。

进一步验证分两层完成：

1. Python 对 R7 原 DLL 数学链逐行镜像，回放得到 `MAE=2.464783 mm / MAX=5.815192 mm / condition=2154.375351`，与交付 CSV 的 `2.464771 / 5.815181 / 2154.375317` 基本重合，证明离线复算链正确。
2. 随后直接把**修改后的 R7.1 `CalibrationV3Analytic.cpp` 编译成原生 C++ 库**，调用其导出 API 对同一 82 点回放，得到：

- `bL = +3.196252891 mm`
- `去零偏前 MAE = 2.936905537 mm`
- `去零偏后几何 MAE = 0.568765711 mm`
- `MAX = 3.323237069 mm`
- `rank = 15/15`（增广矩阵 19/19）
- `condition = 2636.268409`

因此当前旧数据在 R7.1 上的三项 GUI 预计显示约为 `+3.196 / 2.937 / 0.569 mm`。

但同一次 C++ 回放得到 `D3=493.879471 mm`、`D4=-117.000211 mm`，超出既有 8 台激光包络的 `D3<=493.77`、`D4<=-119.14`，所以**旧数据即使几何 MAE 已 <1 mm，仍应被激光包络门拒绝写回**。这是预期安全行为：测量链零偏分离不能顺带放宽机器人几何安全门。

## 9. 本交付包的编译状态

本压缩包中的 R7 交接源代码本身是“网页端 AI 最小交接子集”：Visual Studio 工程引用的部分 MFC 主程序文件、资源目录、Eigen 目录以及若干测试工程文件并未包含在上传包中；当前 Linux 执行环境也没有 Visual Studio/MSVC/MFC。

- **Synthetic bL：PASS，恢复 `2.750000017 mm`（注入 `2.750000 mm`），伪 D5 修正约 `-1.24e-10 mm`**；
- q6/q7 结构零列：PASS；
