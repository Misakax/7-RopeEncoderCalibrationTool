# 证据、版本与数据边界

## V1

V1 是长期使用的权威工具，V3 继承它已经确认的测量约定和 MDH 变换。

但是 V1 源码和界面有明确六轴限制：

- `GetJaco` 是固定 24 列的六轴手写公式；
- Cobot 使用 `DHdelta[9]`、`[10]`、`[11]` 等固定下标；
- 新参数数组没有完整复制七轴原值；
- 只输出六个零位；
- 界面只接收 12 个结果。

2026-08-19 使用 V1 原始 Release DLL 回放两组 2026-06-09 HE3_GY 七轴数据：

| 数据 | V1 标定前 MAE | V1 标定后 MAE |
|---|---:|---:|
| 15:54 | 28.461 mm | 565.334 mm |
| 16:48 | 28.458 mm | 634.102 mm |

这不是否定 V1 六轴工具，而是直接证明：旧 V1 二进制不能通过把 `RbtAxis` 改成 7
就成为七轴算法。

## V2

V2 是 AI 重写版本，曾出现较大误差。用户已明确：2026-08-17 的关节与拉线数据
是 V2 运行产生的。因此这些数据只用于 V2 故障复现，不参与 V3 验收。

## V3

V3 的生产数学核心是解析法：

1. 精确复制 V1 单关节变换；
2. 用前缀/后缀矩阵乘积计算任意 N 轴的精确参数导数；
3. 拉线长度模型为 `L=|P-lambda|`；
4. `lambda` 是固定端坐标，作为 3 个解析未知量共同求解；
5. SVD 伪逆求最小二乘修正；
6. 只对调用者明确开放的参数求解。

测试程序中的有限差分只负责检查解析导数，不进入 DLL 的标定路径。

## 长度账本

| 数值 | 含义 | 放在哪里 |
|---:|---|---|
| 92.7026 mm | HE3 本体最后轴向长度 | 配置原始 d7 |
| 49 mm | 法兰中心至旋转挂点的恒定半径/轴向等效长度 | V1 上位机折入 d7 |
| 141.7026 mm | 92.7026 + 49 | 传入 DLL 的 d7 |
| 43 mm | 拉线编码器内部固定长度之一 | 加到拉线读数 |
| 19.5 mm | 末端连接固定长度之一 | 加到拉线读数 |
| 62.5 mm | 43 + 19.5 | `ropeFixedOffsetM=0.0625` |

49 mm 与 62.5 mm 属于两条不同的长度链，禁止合并成 111.5 mm 后再重复使用。
